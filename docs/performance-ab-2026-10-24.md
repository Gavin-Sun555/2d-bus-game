# A、B 性能优化与重新采样

本轮实施 [优化研究](performance-roadmap-2026-10-24.md) 中的 A、B；C、D 尚未实施。原有车辆数量、60 Hz 物理、转弯轨迹、路权与默认显示同步保持不变。

## 实现

**A：静态边界索引。** 建筑、站湾、道路使用静态包围盒树。建筑和站湾候选恢复原对象顺序；道路使用带安全下界的精确最近查询，保留同距离时原道路的优先级。站湾索引覆盖后方 1200 px 排队走廊、长站台 260 px 出站渐变区和候车亭。方向基向量与道路宽度预计算，不采用近似三角函数。

几何在一次模拟批次开始时校验，嵌套公交控制器共享该批次。普通单次边界查询仍直接读取实时地图；批次内不同车道宽度、无效几何或已失效的缓存使用原扫描路径。读档不保存索引；道路、建筑、站点几何的原地编辑在下一批次检出，修改乘客数不会重建。扩展站湾、重建路口、更新车道宽度显式使索引失效。

**B：路口局部候选。** 先复用现有随车辆顺序移动的网格，查询覆盖最大接近制动范围与出口阻塞范围的候选；已经提交转弯的车辆独立加入，即使旧存档中的位置距原路口很远也保留。每辆小车更新后同步网格，并扩大本批次速度／车长范围上界、登记新转弯车辆。候选按原序号排序去重；精确路权、跟车、扫掠和回堵规则继续执行。独立 StepCar、未准备的索引、异常大范围及测试参考实现回退全扫描。

本轮没有构建新的车道队列模型，也没有并行决策或降低 AI 更新频率。

## 固定模拟基准

本机 M4 MacBook Air，原生 darwin/arm64，Go 1.27.1。seed 20261024，864 小车＋48 辆 AI 铰接公交＋玩家铰接公交，300 次预热、300 次计时；三轮按基线→仅 A→A＋B 串行交替执行。计时期间没有并行运行回归测试。

| 版本 | 3 次 Update 耗时（ms） | 中位数 | 分配次数／Update |
|---|---|---:|---:|
| 基线 | 14.259 / 14.478 / 14.224 | 14.259 ms | 315 |
| 仅 A | 13.482 / 13.490 / 13.418 | 13.482 ms | 315 |
| A＋B | 13.327 / 13.204 / 13.369 | 13.327 ms | 315 |

A 相对基线减少约 5.5%，A＋B 合计减少约 6.5%。这不是带绘制长测，不代表稳定 60 FPS。初步 A 的第一组单独测量中有 16.789 ms 异常高样本，因此以上使用完整交替的三组结果；原始日志全部保留。

- `go test ./... -count=1` 全部通过；新索引与空间感知的定向 `-race -short` 通过；`go vet ./...` 通过。全量测试覆盖既有靠站、绿灯等待、左转、环岛、车型交接和存档回归。

## 第一轮实际绘制长测

seed 5，1280×720 逻辑画布、4 倍驾驶视野、Metal、默认同步；每次 6000 次模拟更新，前 300 次预热。冻结基线和 A＋B 初版各运行三次，顺序为基线／初版、初版／基线、基线／初版。标准计时不启用 profiler。系统上其他用户应用保持原状，没有更改电源或线程设置。

| 版本 | 三次 Draw FPS | TPS 中位数 | Update P50 中位数 | Update P95 中位数 | Update P99 中位数 |
|---|---|---:|---:|---:|---:|
| 基线 | 14.065 / 13.983 / 13.926 | 53.367 | 18.102 ms | 20.505 ms | 24.188 ms |
| A＋B 初版 | 22.285 / 22.091 / 21.023 | 58.877 | 15.883 ms | 18.293 ms | 20.740 ms |

各场景均为 48 辆 AI 铰接车＋玩家；小车 845–864，玩家没有记录到损伤，结束时玩家／AI 车况 100%。模拟的 P50 约降低 12.3%，但绘制仍未流畅。FPS 为 Draw 调用频率，不能当作实际显示扫描率。每次约 100 秒模拟时间，不是连续十几分钟热稳态满载资格测试。

初版另测 8 辆 AI 铰接车，约 59.905 FPS／59.989 TPS，Update P50/P95 为 7.531／10.968 ms，小车 851–864。

新 profile 发现路口候选收集先在网格查询内排序、加入已提交转弯车辆后又排序。最终版改为先收集全部候选再排序一次，仍恢复同样的 ID 顺序；后续最终版数据单列，避免混用阶段。

原始日志、冻结的基线／阶段二进制、CPU profile 与完整轨迹保存在本机 `dist/performance-ab/`。


## 最终版复测与重新采样

合并重复排序后，固定模拟基准三次为 **13.033 / 13.166 / 13.533 ms**，中位数 **13.166 ms**，相对基线约减少 **7.7%**；约 298997 B／315 次分配每 Update。其与初版样本范围有交叠，不把差距单独解释为排序收尾的稳定收益。

| 最终版实际渲染 | Draw FPS | Update TPS | Update P50 / P95 / P99 | 小车范围 |
|---|---:|---:|---:|---:|
| 48 AI 铰接车，第一次 | 26.403 | 59.005 | 15.964 / 18.482 / 20.667 ms | 845–864 |
| 48 AI 铰接车，第二次 | 19.889 | 57.056 | 16.478 / 19.883 / 26.078 ms | 845–864 |
| 8 AI 铰接车 | 59.867 | 59.983 | 8.043 / 11.624 / 13.171 ms | 851–864 |

均另有一辆玩家铰接车、6000 次更新／300 次预热、默认同步、Metal、无 profiler。玩家损伤计数为 0，结束时玩家和 AI 车况均为 100%。最终版只做了两次最大车队标准计时；波动较大，不能声称获得稳定 26 FPS。与基线约 14 FPS 相比有改善，但最大车队仍未达到流畅目标。

另开一次最终版 CPU profile，同一最大车队约 25.012 FPS／58.825 TPS，Update P50/P95 16.055／18.540 ms；不混入上述标准计时。累计采样 86.73 CPU 秒、包含启动预热，热点为：

| 当前调用链 | CPU 累计占比 |
|---|---:|
| 路口队列与冲突判断 junctionQueueSpeed | 10.64% |
| 两节车身预测 AtPose | 9.03% |
| 尾节积分 advanceTrailer | 8.89% |
| 环岛入口预测 | 6.33% |
| 普通小车空间查询 query | 6.10% |
| 铰接车扫掠 articulatedSweptSpeed | 5.48% |
| B 的候选收集与排序 junctionScanCandidates | 2.85% |
| World.CheckBoundaries | 1.43% |

这些调用链有嵌套关系，不能相加。相比此前最终 profile 的边界检查约 9.79%，静态索引确实移除了主要边界扫描成本；剩余路口成本仍包括真正的优先权和精确轨迹冲突计算。B 的候选查询也有维护和排序成本，没有将这部分称为零成本。

**下一步建议 C 优先、D 随后。** 先量化重复预测及缓存命中率，再复用相同输入下的两节车身姿态与几何，保留尾节积分子步和完整碰撞采样。空间查询仍是清楚可见的次级热点，可在 C 后再按证据决定 D。本轮没有继续实施这两项，也不承诺 C 单独就能达到稳定 60 FPS。
