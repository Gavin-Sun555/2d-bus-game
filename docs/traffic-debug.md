# 拥堵 debug 模式

从项目目录启动：

```sh
./busgame --debug
```

也可以通过 `./build.sh run --debug` 编译后启动。

macOS 应用包也可以直接运行其可执行文件：

```sh
"./2D Bus Simulator.app/Contents/MacOS/busgame" --debug
```

`-debug` 与 `--debug` 均可使用。不带此参数时，不启用拥堵监测或生成 debug 存档。该开关属于本次进程，不会写入游戏设置；加载存档、换地图或切换模式后仍保持本次启动的 debug 状态。

AI 公交或当前密度下的小车，连续停留在两像素范围内且速度低于 3 px/s，超过附近路口两个完整信号周期后，会保存一次现场。周期取当前路口完整相位图，包含直行、左转和黄灯，计时使用仿真时间；加速模拟也会加速计时。无信号灯时采用默认完整周期。规划暂停时不累计，正常开门上下客及车型更换等待不计为拥堵。

因死锁重置/替换小车、重置公交，以及公交局部重新定位脱困时，在实际改变位置和路线状态**之前**保存现场。车辆正常驶出地图或手动重新规划线路不会触发此类快照。

文件位于普通存档目录内的 `debug-saves`，启动及保存时终端会打印完整路径。macOS 默认位置：

```text
~/Library/Application Support/2d-bus-game/debug-saves/
```

`congestion-时间戳-序号-车辆类型编号.json` 使用普通游戏存档格式，包含完整城市、车辆、路线、乘客和信号灯状态，便于回放。`metadata.debug` 额外记录触发原因、车辆编号、位置、最近路口、停滞时长、完整信号周期及附近车辆的状态。保存的相机初始位置指向现场，玩家车辆本身不会移动。

同一停滞过程只记录一次；同一路口的同类事件在两个周期内合并，长时间拥堵与重置事件分别记录。最多保留最近 20 份 debug 存档，普通手动存档及自动存档不会被覆盖。写入失败会在终端报告，并在仿真时间五秒后允许重试。
