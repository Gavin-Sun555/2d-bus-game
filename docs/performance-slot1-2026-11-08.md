# 存档 1 高速与密集车流性能优化（2026-11-08）

使用本次工作开始时存档 1 的副本，在 Apple M4 上固定随机种子 5 回放。保留全部 72 辆 AI 公交和 864 辆小车，没有通过减少车辆、降低模拟频率或碰撞采样精度提速；原存档未被覆盖。

## 瓶颈与修改

1. 小车逐辆处理时，原先每车都扫描全部公交并重复寻找并线请求关联的站点。现在每次车流更新准备一次有有效请求的公交列表和站点引用，保持公交顺序、玩家优先权以及全部刹车公式。独立调用 StepCar 时重新准备，避免读到旧请求、旧站点。
2. 并线冲突检查反复创建双方的路径碰撞体数组。现在复用管理器的两个独立临时缓冲区，并用栈上的短路径数组；缓冲区不交给正在行驶的车辆，单个缓冲区保留容量上限为 4096。
3. 高速预测中，部分明显不可能碰撞的公交仍执行完整铰接车积分。现在先检查保守空间边界；边界同时包括目标车头、所有可能的车尾位置及预测失败后退回的原始车身。只有能证明分离才跳过，其他情况仍运行原来的精确积分和碰撞检查。角度异常、尺寸异常或负边距等情况退回原检查。

## 验证方法

离线回放：预热 120 次，再测量 1800 次生产 Game.Update。统计 CPU 更新耗时及分配，不包含绘制；CPU profile 单独采集，避免将采样开销混入正式计时。新增完整城市存档状态 SHA-256 对比。

实际窗口：1470×915 窗口、游戏原有 LayoutF 和图形预热包装器、60 Hz 垂直同步。总共 1800 次更新，排除前 120 次。记录 Update、Draw 提交耗时、两次 Draw 开始之间的间隔；Draw 提交耗时不是 GPU 完成时间。原生回放包含 1016 个 ≥140 km/h 高速更新和 306 个路口更新。864 辆小车始终参加全城模拟；本段没有达到“玩家 800 世界单位内至少 12 辆小车”的额外密集视野分类，不把本结果冒充为所有拥堵视野的帧率保证。

测量使用独立窗口，未启用主程序的声音/报站系统。短回放无法排除长时间运行、其他路段、系统调度或 GPU 同步产生的尖峰；关注分位数，不能仅看平均 FPS。

## 测量结果

离线正式计时（无 CPU profiler，最后一轮；优化前另一次复测平均 8.64 ms、P99 15.58 ms）：

| 指标 | 优化前 | 优化后 | 降幅 |
| --- | ---: | ---: | ---: |
| 平均更新耗时 | 8.65 ms | 7.82 ms | 9.6% |
| 更新耗时 P99 | 15.62 ms | 10.84 ms | 30.6% |
| 每次更新分配 | 51,635 B | 32,871 B | 36.3% |

两轮真实窗口回放的范围：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 平均更新耗时 | 8.81–8.92 ms | 8.17–8.28 ms |
| 更新耗时 P99 | 15.60–15.63 ms | 11.17–11.46 ms |
| 画面间隔 P99 | 24.64–32.52 ms | 18.32–18.39 ms |
| 平均绘制频率 | 59.23–59.27 FPS | 59.98 FPS |

首轮高速段更新耗时 P99 从 15.71 ms 降至 11.29 ms，路口段从 10.18 ms 降至 10.06 ms。本段路口原本就比高速段轻，不能把高速段的降幅套用到所有路口。

优化后原生窗口仍有 28.7 ms 左右的最慢画面间隔，不能声称彻底消除卡顿；主要改善是高速时反复出现的慢帧。

两种回放分别在优化前后获得完全一致的完整城市存档状态哈希；两种模式更新总次数不同，因此不跨模式比较哈希。离线回放玩家行驶距离一致、耐久 79→79，AI 公交最低耐久 100，小车全程 864 辆。原生回放也保留 72 辆 AI 公交和 864 辆小车。

原始分布、车辆数和状态哈希见同目录 `performance-slot1-2026-11-08.json`。其中 `offline_after_profiled` 为独立采样分析，正式无采样结果为 `offline_after`。

## 回归验证

- 12000 组不同车型、弯道预测和铰接失败回退，与原始精确碰撞检查逐项比较。
- 有效、过期、开门、已移除的并线请求，以及稀疏/重复站点 ID、站点列表替换，与未缓存让行规则比较。
- 800 组连续并线检查与冻结的旧实现对比，检查临时数组复用不会改写车辆路径。
- autopilot、traffic、sim、game 相关路口/车道/转弯/信号/靠站/预测/恢复/存读档测试通过；沿用此前已确认的三个旧失败排除项：TestSavedSlot5RearBerthImmediateDockBehindArticulatedBus、TestMetropolisNorthRingMergeBehindQueue、TestSlot2CarBusMergeDeadlockResolution。
- `./build.sh app` 成功，生成当前 macOS 应用包。

## 复测命令

先复制存档到临时路径，再编译前后版本的测试二进制；顺序运行，计时期间不并发执行编译或其他测试：

```sh
go test -c ./game -o /tmp/bus-perf.test
BUS_PROBE_SAVE=/tmp/slot1-copy.json BUS_PROBE_OUTPUT=/tmp/bus-probe \
  BUS_PROBE_WARMUP=120 BUS_PROBE_TICKS=1800 \
  /tmp/bus-perf.test -test.run '^TestPerformanceProbe$' -test.v
BUS_NATIVE_SAVE=/tmp/slot1-copy.json BUS_NATIVE_OUTPUT=/tmp/bus-native \
  BUS_NATIVE_FOCUS=1 /tmp/bus-perf.test
```

`BUS_PROBE_CPU=1` 可额外生成 CPU profile；`BUS_NATIVE_TICKS` 可延长原生回放。原生测试会在输出目录创建自己的输入存档副本。
