# P2 慢帧复查与可选优化（2026-10-27）

后续实验已完成，实际保留／撤回及两轮 15 分钟结果见 [P2 实验报告](performance-p2-experiment-2026-10-27.md)。以下保留实验前研究。

研究基线为 `e6ab238`，包含两组公交互锁修复。本轮没有修改生产代码、用户存档或 Git 配置，没有提交或推送 GitHub；诊断源码通过 `dist/` 内的 Go overlay 加载。

## 判断

剩余问题应优先从模拟尾部耗时和连续补更新入手。历史 Draw 回调提交约 1.4 ms，单看绘制 API 调用次数或平均 FPS 不能定位剩余 P2。不能假定此前已确认并预热的着色器编译仍是这轮 31 ms P99 的主因，也不能把所有 Update 墙钟时间认作纯 CPU 计算。

P1 修复后更多公交可以正常行驶，实际负载会改变。现有 900 秒原生性能仍属于 `423a3e8`，不是本次修复版本的重新验收；应先补一轮新版本 15 分钟前台全屏基线，并另做短时跟踪，避免用带 profiler 的数据作发布门槛。

## 历史原生数据的重新拆解

对 `dist/release-0.0.7-final/native/events.json` 第 30～900 秒全部 51,538 个绘制间隔重新分析，按相邻 Draw 开始时间求间隔，并分别累计其中 Update 墙钟、前次 Draw 墙钟及回调外剩余时间。

| 项目 | 结果 |
|---|---:|
| 绘制间隔 P99／P99.9 | 31.077／49.494 ms |
| 超过 25 ms | 557 次 |
| 其中含至少两次 Update | 551 次，98.92% |
| 慢间隔内 Update 合计中位数 | 30.325 ms |
| 慢间隔回调外剩余中位数 | 0.933 ms |
| 最长间隔 | 94.734 ms |
| 最长间隔中的 Update | 5 次，合计 91.976 ms；最长单次 18.475 ms |
| 同一最长间隔中的前次 Draw／回调外剩余 | 1.598／1.160 ms |

这说明大量慢间隔伴随连续补更新，不能解释为一次 31～95 ms 的 Draw 函数计算；但这些数字并不能单独确定最初错过预算的原因，也不等于实际屏幕呈现时间。引擎等待、被系统暂停等仍可能计入回调墙钟，需要 runtime／系统跟踪来区分。[Go 诊断文档](https://go.dev/doc/diagnostics)也区分 CPU 热点采样与延迟跟踪的用途。

|---|---:|---:|---:|---:|
| 30～120 秒 | 32.85 ms | 92 | 9 | 843～864 |
| 120～300 秒 | 33.32 ms | 332 | 8 | 829～843 |
| 300～600 秒 | 18.15 ms | 40 | 0 | 792～829 |

最初数分钟更影响整体 P99；后期约 717 秒的一段更新耗时升高又影响 P99.9/max。不能仅归因为越玩越热：车数、运动状态、公交等待和系统负载都在变化。每时段 GC STW 总暂停约 2.8／5.9／10.0／9.7 ms，不能用它直接解释几十毫秒连续间隔；后台 GC 和分配辅助仍须单独诊断。

## 当前源码的新采样

M4、Go 1.27.1、darwin/arm64；48 AI 铰接公交＋玩家、864 小车，固定种子，300 tick 预热、3600 measured tick。单独运行 CPU/分配采样，不并行跑回归或其他基准；测量结束记录接电、100% 电量。CPU profile 包含启动、校准和预热，共 42.78 CPU 秒；纯模拟不含 Draw/GPU。

## 可选方案与优先级

### 1. 路口轨迹派生几何复用与保守分组筛选——优先

`JunctionLeaderGap` 对同一份走廊反复计算段长度、单位方向、累计距离；`separatedBodies` 在整体包围盒相交后仍逐体配对。

分成两个独立小实验：先缓存同一次或同一版本走廊的精确派生几何；再为连续若干采样体建立保守包围盒，整组确实分离才跳过，否则继续原 SAT。保持采样、候选次序、最近段等距规则、车宽膨胀与原浮点运算顺序，不缓存路权或灯态。

依据是当前路口排队 13.09% 的热点，收益需要 A/B 验证，不能期待消除整个 13%。风险在移动连接段、裁剪、尺寸变化及已发布走廊的失效；建议先限制在单次检查内，再扩大复用范围。

### 2. OBB 检测复用精确坐标轴和半径——适合作为另一个小实验

`CheckOBBCollision` 同时构造 `u=UnitFromAngle(h)` 与 `v={-Sin(h),Cos(h)}`，还对大量重复车身重算半径。可验证垂直轴的逐位复用，并在一次多障碍扫描中预计算不可变几何。保留原四轴投影、比较次序、法线和深度；不改成近似三角函数，也不直接将所有 Hypot 阈值改成平方距离。

当前该函数累计约占 4.86%，因此属于有限的节省机会。改动影响碰撞基础函数，必须覆盖接触临界点、负零、NaN/Inf、不同膨胀量以及真实分离输出，不能只验布尔结果。

### 3. 姿态精确缓存冲突诊断，再试双路／分区缓存

`AtPose` 当前累计 13.88%，命中约 44%。先区分首次访问、源姿态变化与真正的槽位冲突；只有冲突占比值得处理时，再对 128 槽直接映射尝试双路或按调用来源分区。计入 Bus 复制、哈希和缓存体积成本。

保持完整逐位键、原始积分起点和尾节子步。这不恢复此前暂缓的逐段累进预测；命中率低本身不能证明加大表就有效。验证轨迹一致、缓存内存上限、常见／最大车队和原生尾部耗时。

### 4. 为其余公交扫掠消费者单独收集保守候选

此前“16 次未来姿态一次收候选”已实施，不能重复计作待做项目。可进一步研究 `controlSweptSpeed` 或 `junctionSweptSpeed` 各自的一次扫描，减少多轮遍历远处障碍。

当前两个调用链分别约占 7.32%／5.66%，但包含姿态和实际检测，不能全算成扫描收益。需覆盖后方高速车辆、转弯预测、整条已承诺轨迹、尾节及每辆车更新后的新位置；不能按当前中心距离截断全部公交感知。风险和回归量高于前两项。

### 5. 路口缓冲容量与生命周期复查

本轮证实既有几何后缀缓存正在命中，仍有容量增长。先统计哪类车／模板／所有权重置在分配，分别查看长期稳定阶段，再考虑精确预分配、容量保留或缩减复制。

已发布给别车读取的 `JunctionCorridor.Bodies` 必须保持独立，不能拿同一临时数组覆盖；持续大地图需要容量上限。主要收益是减少分配和辅助工作，当前数据不支持把 GC 参数调整列为首选。Go 的 [GC 指南](https://go.dev/doc/gc-guide)也说明了分配、GC 辅助工作与内存／CPU之间的取舍；不能把降低分配百分比直接等同于 P99 改善。

### 6. 静态画面分块缓存／实际提交批次优化

道路、建筑、树木可使用有显存上限的分块几何或纹理；车辆、灯态、乘客、路线和 HUD 继续动态更新。先查看实际引擎命令，再判断是否值得缓存。[Ebitengine 官方性能建议](https://ebitengine.org/en/documents/performancetips.html)指出相邻兼容调用会自动合批，并提供 `ebitenginedebug` 查看实际提交。

模拟风险较低，但需验证旋转、缩放、全屏、接缝、地图编辑失效及内存。历史 Draw 提交约 1.4 ms，可争取余量，但未确认 GPU 瓶颈，不能据此承诺解决 31 ms P99。

### 7. 构建／M4 调度的小范围实验——最后考虑

PGO 用混合地图、车队和正常运动阶段的代表性采样重试；[Go 官方 PGO 文档](https://go.dev/doc/pgo)强调采样代表性。旧实验约 1% 的差异并不稳定，本轮未做新 A/B，不承诺收益。

只有跟踪明确指向线程等待后，再比较默认线程配置、已有 single-thread 选项和少量 GOMAXPROCS 配置。它不是绑定 M4 性能核的开关；ARM64、Metal 和 Game Mode 元数据已具备，不能重复计作新优化。当前没有新证据支持改默认线程、禁用垂直同步或强改系统优先级。

## 建议执行顺序

1. 新版补一次 15 分钟无 profiler 原生前台全屏基线，另采短 trace 定位慢区间；不操作用户存档或系统权限弹窗。
2. 先试方案 1 的两个小实验，再试方案 2；分别冻结前后版本做交替 A/B，不同时叠加。
3. 若能将模拟 P99 降至约 13～14 ms，可能为 16.67 ms 总预算留下更多余量；这是工程目标，不是 FPS 承诺。实际以绘制间隔 P99 ≤25 ms、P99.9 ≤50 ms及长间隔事件复核。
4. 重采热点后再决定 3～6；构建／调度实验排在有明确重复计算证据的项目之后。

不恢复此前暂缓的模拟／渲染流水线与逐段尾节积分，也不通过降低物理频率、减少车辆或放松碰撞检查制造收益。P1 回归、站台／环岛通行、车况及有效运动量继续作为验收条件。

原始证据保留在 `dist/p2-review-2026-10-27/`：历史逐帧重分析、当前 CPU/分配 profile、计数器 overlay、基准日志。结构化结果见 [JSON](performance-p2-review-2026-10-27.json)。本轮是研究，未做新优化前后效果对照，也未重跑 900 秒原生资格测试。
