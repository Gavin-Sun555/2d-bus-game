## Debug log 与修复原因

原始 debug 目录共 16 个现场：2 个小车 `deadlock-reset`，14 个 `two-signal-cycles`。告警主要聚集在西侧路口、23 号站附近，不能仅看单辆告警车辆就认定信号灯有问题。

1. **公交 124 与 122 的转弯并道互锁。** 前车尚未完成路口并道，后车有明显夹角；原先把已完全位于后方、实际车身间距充足的静止车辆也当成并道间隙占用者。修正只针对有活动转弯并道意图的车辆，按两节真实车身的投影间距判断后车，保留车身碰撞与扫掠检查。移动、相撞、对向、过宽并道等情况仍拒绝。
2. **23 号站公交 126 越过前泊位后停住。** 站台跟车限速错误地使用了后方 127 的速度；越过前泊位后，车头看似在站边，但整车已超出有效上下客范围。修正前后车判断；对于路径已结束、仅略过泊位、停止等待且无服务任务的车辆，验证短距离倒车能将完整车身带回有效上下客位置，再按原控制器倒车靠站。公交 126 原始现场在 3.23 秒内恢复上下客，无穿车或重定位。
3. **小车 7707 与公交 172 的拖挂互锁。** 长测第 5 分钟发现：公交车头和拖挂的相对夹角不大，但拖挂仍斜在小车车道上。旧逻辑因相对夹角小而把它当成普通顺直排队，每帧清空小车的死锁计时器。现在同时检查拖挂相对于小车道路方向的角度；正常红灯队列仍按原规则等待，绿灯放行后拖挂仍形成楔形阻塞时启动现有安全倒车让位。
4. **12 号站公交 94 被站台边界和后车 85 同时夹住。** 94 的进站轨迹需要少量后退才能避开静态边界，后车又位于退路内。现在先证明“后方让出空间后能够安全倒车，并恢复前行”，才向后车发让位请求；后车独立检查完整倒车轨迹，前车在后续帧重新检查真实车流后才倒车。后车稍有偏斜也可接受请求，仍保留车门、上下客、信号灯、路口和车身扫掠限制。捕获现场的双公交回归在 13.05 秒内让 94 恢复上下客。
