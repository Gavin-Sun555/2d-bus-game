# 0.0.7 三组 P1 碰撞修复验证

本轮针对首次发布资格验收发现的三组碰撞进行修复，使用原始合成存档和相同种子复测。没有修改碰撞扣损、隐藏车辆或降低长测安全门槛。证据目录为 `dist/p1-fixes/`。

## 原因与改动

1. **都会铰接车撞候车亭（seed 700）**：空站台且路线终点已指向前泊位时，控制器跳过局部停靠对正，车辆在车头仍朝向路侧时加速。铰接车现在保留局部低速对正，待车身平行后完成前泊位停靠；普通车的原有快捷路径保持不变。
2. **自定义地图普通公交环岛碰撞（seed 505）**：内圈小车驶出时，原有检查只考虑目标道路上同方向车辆，漏掉外圈仍在环行的公交。新增出口前的实际曲线预测，对公交两节车身逐一检查，冲突时提前减速，公交通过后恢复驶出。
3. **自定义地图铰接公交环岛碰撞（seed 705）**：除上述内圈驶出冲突，还发现后续外圈小车追撞已停住的尾节。原先静止公交路径豁免和环行跟车距离只使用前节。现在静止车辆路径检查覆盖两节，跟车距离及平行车道判定使用整车包围盒。

出口预测仅在即将驶出环岛且附近存在公交时运行，保留普通环行和相互分离车道的既有规则。预测复制小车曲线状态，不推进真实车辆或真实路径。

## 验证结果

- 三份首次验收捕获的原始存档各回放 360 帧（6 秒），全部通过；没有修改存档文件。
- 原始种子、864 小车、8 辆 AI 的两分钟长测：

| 场景 | 玩家行程 | 车况 | 结果 |
| --- | ---: | ---: | --- |
| 都会混合车队，seed 700 | 11,202 px | 100% | 安全、容量、位置连续性、车队进度及第 60 秒存读档检查通过 |
| 自定义普通公交，seed 505 | 10,681 px | 100% | 原碰撞不再复现，两分钟安全门槛通过 |
| 自定义混合车队，seed 705 | 1,925 px | 100% | 原碰撞及后续尾节追撞不再复现；通过既有安全门槛，但存在下述环岛互等限制 |

- 全量 `go test -json ./... -count=1 -timeout=30m`：**8,746 个测试／子测试通过，9 个按配置跳过，零失败**。通过数包含父级测试，不等同于独立场景数。
- 新增 35 个测试／子测试覆盖：四方向、三车型、玩家／线路 AI 的内圈驶出避让；停住的铰接车尾节保护与恢复行驶；四方向普通／狂暴模式的空站台靠站与最终停靠。
- 相关环岛及停靠用例的 `-race` 检测通过；`go vet ./...` 和 `git diff --check` 通过。
- 已重新编译根目录的 `busgame` 与 `2D Bus Simulator.app`；未自动启动、载入或保存用户游戏。用户存档 SHA-256 与首次验收备份记录一致。

### 当时尚未解决的环岛互等

2026-10-24 后续修复及验证见 [环岛队列与性能复测](../roundabout-queue-performance-2026-10-24.md)。下文保留本次 P1 修复结束时的历史状态。

延长检查发现，自定义铰接车场景约两分钟行程仅 1,925 px，队列在环岛出口附近互相等待。第 60 秒存读档检查通过，全部 AI 达到现有最低进度门槛，但这不证明通行顺畅。跟车保护阻止了先前的尾节追撞；不能把随后的无扣损等待当作完整的通行修复。

本轮额外尝试了小车被侧推后的连续回环、出口再绕行和低速改向恢复；这些方案未解决完整队列互等，均未保留在最终源码中。该互等作为独立的待修问题记录，不能据此解除发布暂缓。
