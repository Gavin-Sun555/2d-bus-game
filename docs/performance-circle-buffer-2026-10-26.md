# 圆形绘制缓冲复用：实现与对照（2026-10-26）

本轮保留这项优化。三组原生全屏交替对照中，游戏分配速率从约 **79.55 MB/s 降至 30.02 MB/s（减少 62.3%）**，Draw 提交耗时 P99 从 **2.032 ms 降至 1.488 ms（减少 26.8%）**。平均帧率前后都约为 60 FPS，绘制回调间隔 P99 基本持平，短测不足以证明长期偶发卡顿已消失。

## 实现

- `internal/view/primitives.go` 的填充圆和圆环使用同一个固定大小的顶点数组，每次只提交有效切片。
- `internal/view/circle_mesh.go` 按细分段数懒加载单位圆方向与索引模板。填充圆保持 12–128 段，圆环保持 12–256 段；模板不以半径、颜色、坐标、视口或主题为键。
- 保留原来的角度计算、float32 转换、顶点/三角形顺序、抗锯齿覆盖及透明度计算。颜色和位置每次重建，不会复用旧主题或旧视口的数据。
- 固定顶点数组为 1024 个顶点；即使所有合法模板都出现，逻辑有效载荷上限约 1.58 MiB（含模板切片头和顶点数组，不含分配器管理开销）。常用场景只初始化实际出现的段数。
- 沿用现有 `sharedQuadVertices` 的单绘制线程约定。Ebitengine 2.10.4 的 `DrawTriangles` 会先复制索引并转换顶点，再提交内部绘制数据；下次绘制可复用缓冲。私有网格构建函数的返回切片必须在下次构建前提交，不提供并发构建接口。

生产改动限于 view 包内的圆形几何构建和缓存，没有修改车辆、碰撞、让行、存档及模拟/渲染线程结构。

## 验证

1. 保存优化前的独立网格实现作参考，逐段数检查全部合法细分档位、段数切换边界、透明色、AA 开关、极小/无效半径及宽圆环，顶点和索引与原版一致。
2. 原生 Metal 像素测试覆盖 0.25/1/2/4 倍缩放、透明混合、裁剪子图及填充圆/圆环连续交替绘制。两版在同一个渲染目标上分别清屏绘制，避免不同目标图像和图集位置混入对照；最终输出逐字节相同。PNG SHA-256 均为 `14de3d3475cefe69344b8db4607d785d44e33f998986d2affa4a87660b9d84d3`。
3. 热网格构建的 `AllocsPerRun` 为零。微基准每次构建一个半径 13 的填充圆及一个半径 29 的圆环，三次结果的中位数为：

| 指标 | 原版 | 复用版 |
|---|---:|---:|
| 每组构建耗时 | 2811 ns | 984.5 ns |
| 每组堆分配 | 17760 B | 0 B |
| 每组分配次数 | 4 | 0 |

上述零分配指已经初始化模板的网格构建，不代表整场游戏或下游绘制引擎零分配。

全量常规测试通过；view 包 race 测试、原生像素对照、`go vet ./...` 和 `git diff --check` 通过。原生 GPU 测试通过 opt-in 开关在 `TestMain` 的 macOS 主线程运行，默认常规测试不启动图形窗口。

## 整场游戏对照

M4 MacBook Air 接电运行，Metal、原生全屏、1280×804 逻辑画布、4 倍驾驶视野；48 辆 AI 加玩家全部为铰接车，864 辆小车在全部统计窗口持续活动。玩家默认狂暴巡航 80 km/h，AI 配置 30–80 km/h。两版都包含上一轮通行修复，基线通过 Go overlay 只恢复优化前的圆形绘制函数。

正式采样顺序为 A1→B1→B2→A2→A3→B3，每场 60 秒，分析第 5–60 秒全部回调。正式采样期间不并行运行大型测试、不启用 CPU profiler/trace，六场均无失焦或退出全屏，玩家及全部 AI 车况保持 100%。两版测试包均声明游戏类别及 Game Mode 支持，实际 Game Mode 开启状态未独立观测。

| 指标 | 原版 | 复用版 |
