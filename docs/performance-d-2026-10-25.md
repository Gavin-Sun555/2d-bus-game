# D：小车候选收集与网格查询优化

本轮基线是包含最新外侧停站死锁修复的当前代码，不能直接与历史 C 轮次的数字计算加速比。冻结二进制、轨迹、测量日志位于 `dist/performance-d/`。本轮不改存档格式、车辆数量、60 Hz 物理、尾节积分、安全余量、扫掠密度及车辆顺序更新。

## 实现

- 常用地图范围采用稠密网格目录，直接取得桶，避免每个空单元都查哈希表。单元尺寸仍为 512 px，目录最多 256×256 个指针（64 位平台最多 512 KiB），只在车辆超出预留范围时扩大。目录以外及巨大稀疏地图使用原样的哈希查找，不丢弃范围外车辆。
- 每轮重建只清理实际使用过的桶，复用桶对象及 ID 缓冲；跨格移动仍在每辆车更新后立即反映到索引，碰撞挤推后仍重新查询。
- 对较多候选，用位集合按原车辆槽位升序输出；小集合保留排序。结果保持原先顺序，不依赖网格遍历顺序或车辆自身 ID。位集合每次清空，车辆增减／重建后使用当前槽位，不跨帧复用候选状态。
- 普通小车候选延迟至超车、并线或跟车规则实际消费时收集，同一辆车的一次 StepCar 内复用。查询半径在规则可能制动前冻结；远程超车前车 ID 查找仍检查全部活跃小车；路口候选使用独立缓冲。

没有缩小原 1800 px 最小感知范围，也没有实施更高风险的按用途缩短跟车／并线范围：路口已承诺轨迹的跟车判断不只依赖当前中心距离，需要独立证明后才能缩减。因此本轮实施 D 中的目录、维护、顺序输出和按需收集部分。

## 一致性与安全

- 最大车队（48 AI 铰接公交＋玩家＋864 小车），固定种子下 1800 帧逐帧状态轨迹一致，SHA-256：`eb1d70ed97f883bd31438aaa64e1261f060414a8baf9dce1ee6b7e61055b67d7`。
- 独立按车辆当前单元扫描的 oracle 覆盖 9 轮人口增减／清空、负坐标、随机跨格移动、目录增长、目录外移动及百万像素稀疏范围；有序和无序查询候选均一致。
- 原全扫描感知对照、全配对碰撞挤推对照和新增查询缓冲隔离检查通过。

## 测量方法

Apple M4、原生 ARM64，默认线程数和显示同步。性能轮次串行执行，不与回归测试或 CPU profiler 混跑。固定模拟基准为 seed 20261024、48 AI 铰接公交＋玩家、864 小车，预热 300 更新、测量 300 更新，前后交替共三组。

| 固定模拟基准 | 三次 Update（ms） | 中位数 | 每 Update 分配 |
|---|---|---:|---:|
| 本轮基线 | 12.991 / 13.153 / 13.010 | 13.010 ms | 约 298986 B／315 次 |
| D | 12.116 / 12.023 / 12.049 | 12.049 ms | 约 298990 B／315 次 |

中位耗时减少约 **7.39%**，三组 D 均低于对应基线。这是固定模拟窗口的结果，不等同于帧率提升。新增目录与桶对象的初始化主要发生在预热阶段，分配次数不变不代表常驻内存没有增加。

## 最大车队真实绘制

seed 5、Metal、1280×720 逻辑画布、4 倍驾驶视野、864 小车＋48 AI 铰接公交＋玩家。每次 6000 更新，前 300 更新预热，顺序为基线→D、D→基线；无 profiler。记录完整结果，不挑选较好的一组。

| 版本／轮次 | Draw FPS | Update P50 / P95 / P99（ms） |
|---|---:|---:|
| 基线 1 | 25.357 | 15.752 / 17.721 / 18.692 |
| D 1 | 41.871 | 14.810 / 16.638 / 17.704 |
| D 2 | 39.615 | 14.893 / 16.636 / 17.714 |
| 基线 2 | 26.115 | 15.715 / 17.463 / 18.463 |

两轮的中位数：**Draw FPS 25.74→40.74（约 +58.3%）**；Update P50 **15.734→14.851 ms（约 −5.61%）**，P95 **17.592→16.637 ms（约 −5.43%）**。跨过同步／调度门槛时 Draw 调用频率变化不会与模拟耗时成比例；FPS 是计时窗口内的 Draw 调用次数／墙钟时间，未测屏幕实际呈现间隔。

四轮均保持 845–864 辆小车，玩家损伤事件 0，玩家和全部 AI 公交结束时车况 100%。D 两轮最大 Update 分别约 39.8 和 32.2 ms，基线第一轮也约 38.8 ms，不能据此声称消除全部尖峰。最大车队仍未达到稳定 60 FPS，本轮每场约 100 秒模拟时间，尚不是连续 10–15 分钟热稳态资格验收，发布 HOLD 不因本轮性能结果自动解除。

## 常用车队

同样的实际绘制场景改为 8 AI 铰接公交＋玩家，每版各一轮 3600 更新、300 预热，始终维持 864 小车：

| 版本 | Draw FPS | Update P50 / P95（ms） | 最大 Update（ms） |
|---|---:|---:|---:|
| 基线 | 59.978 | 8.878 / 11.424 | 23.531 |
| D | 59.979 | 7.939 / 10.381 | 21.133 |

两版均接近 60 FPS；D 的单次样本 P50 耗时少约 10.6%，不能解释为帧率进一步增长。两轮玩家无损伤，玩家和全部 AI 公交结束时车况 100%。每版只有一轮，此项主要核对常用场景没有明显退步。
