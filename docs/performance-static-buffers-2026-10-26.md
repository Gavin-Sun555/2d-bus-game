# 道路边界缓存与临时数组复用：实施及复采样（2026-10-26）

## 变更范围

按上轮建议依次做第1、2项。既有工作区其他改动保留；此前删除的逐段尾节预测、模拟/绘制流水线没有恢复。原始数据、冻结构建及源码哈希在 `dist/performance-static-buffers-2026-10-26/`。

1. **道路边界**：把东西/南北两个方向的端点值放进现有boundaryGeometryCache，沿用原道路遍历与Math Min/Max顺序。仅在Begin/EndBoundaryQueries批次内使用已验证缓存；批次外扫描实时道路。地图直接编辑、读档、异常地图导致缓存失效时沿用原扫描。零端点保留扫描，因为已有地图验证把+0和-0视为相等，需要保持原端点位模式。
2. **临时几何**：每个控制器复用junctionAdmissionSpeed的临时OBB数组，以及roundaboutEntryObstacleSpeed的临时OBB/原顺序障碍索引数组。索引只在同步扫描中读取输入观察列表，不把完整车辆观察结构写进长期缓存；不发布这些数组为其他车辆的JunctionCorridor。Reset释放缓存；超过4096个轨迹体或2048个环岛障碍的异常大输入不长期保留工作区。没有改变采样间隔、碰撞边距、车序、路权或驾驶决策。

缓冲复用会保留一定容量；累计分配减少不等于常驻内存同幅下降。没有试图跳过检查、提高速度或减少车数。

- 完整go test ./...、定向race、go vet ./...通过。最终修订后重新执行，不沿用首版结果。
- 原版、仅第1项和两项合并版，48辆AI+玩家连续1800 tick轨迹SHA256均为`eb1d70ed97f883bd31438aaa64e1261f060414a8baf9dce1ee6b7e61055b67d7`。

## 首版被淘汰的原因

首版虽然减少分配次数，最大车队累计分配却从约299KB/tick升到793KB/tick。分配profile和编译器逃逸分析定位到：缓存从整个entryFrame结构取出的数组字段，让obstacleSpeed中的大体积departureSweepCache逃逸到堆。修订后先缓存独立数组，消除了大结构逃逸；但完整观察结构的缓冲仍有写入/保留成本，该轮又出现尾部耗时恶化（尖峰归因未确认，不据此断言是数组缓存导致）。最终进一步改为OBB和原槽位索引视图，按原顺序即时读取观察对象，并仅在真正需要比较时构造路口轨迹。两份被淘汰原型保留为prototype1/2；最终结论只使用索引版。

## 测量方法

Apple M4 MacBook Air、16GB、Go1.27.1 darwin/arm64。全部性能采样串行，不与编译、回归、race混跑。冻结原版、仅第1项、最终合并版，各三次交替固定模拟基准；每场300 measured tick，常见车队600 tick预热，极限车队300 tick预热。

真实绘制采用seed5、Metal、1280×720逻辑分辨率、4倍驾驶视野、VSync开启、默认线程；48辆AI铰接公交+玩家，1800更新/300预热，原→后、后→原。每轮记录供电前后状态。Draw FPS为回调次数/墙钟时间，不是显示器呈现间隔；未声称完成全屏GPU或10–15分钟热稳态资格验收。

独立CPU/分配采样另行运行：最大车队1800 measured tick；环岛与当前存档各900，均预热300后启动CPU采样，allocs做前后差分。两版使用相同配置/输入；不将有profiler数据与无profiler计时横比。

## 复采样后的热点与结论

最终独立模拟最大车队profile约15.98 CPU秒，累计占比：小车junctionQueueSpeed 14.71%，Bus.AtPose 10.39%，其中advanceTrailer 9.51%；JunctionLeaderGap 4.63%，separatedBodies 4.32%。调用链嵌套，不能相加；占比变高也不等于绝对成本回退，因为总CPU分母与采样窗口会改变。

道路边界扫描已不再是该场景明显的CPU热点。分配profile中，剩余约86.32%的累计分配落在carJunctionBodies调用链，AppendPathBodies自身约73.61%。本轮只复用了公交入路口/环岛临时数据，未扩大改写小车已发布轨迹的生命周期。

后续更值得研究的是：路口轨迹段派生数据复用、分组保守剔除，以及小车轨迹构造的剩余分配。铰接姿态预测仍较贵，当前保持原独立预测物理和检查密度。此前删除的逐段预测及模拟/绘制流水线继续不启用。

结论：保留道路边界缓存和最终索引版临时几何复用。CPU收益小幅，分配压力下降较明显；本次没有证明长期热稳态、全屏呈现或所有拥堵状态都已流畅。
