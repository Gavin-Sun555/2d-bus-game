# 第 1、2 步性能优化：静态查询与转弯缓存

## 已实现范围

- 地图道路、环岛和路口坐标只在每次交通更新开始时验证一次。道路宽度、路口包围盒、转弯半径及环岛归属按地图与车道宽度缓存；路口包含判断也使用空间网格。
- 小车的信号判断、路口准入、转弯触发及行驶走廊发布只遍历附近路口。候选保留原数组顺序，查询范围包含制动距离、车道宽度、本次移动量和已提交转弯所在路口。无索引时回退原查询。
- 每辆小车保留转弯路径模板、路径点缓冲、车身样本及行驶走廊缓冲。随车辆移动，只重算当前位置到下一路点的连接段，复用后续不变的车身采样；采样间距和接缝重复点保持原值。
- 转弯模板与正在行驶的转弯状态分开：移动进度和裁剪路径不会修改模板。道路、车道宽度、车辆尺寸、入/出车道、横向位置或路口配置改变时失效；新生成或重排的小车按对象身份重新分配缓冲。
- 缓存均为运行期数据，不写入存档。重建地图清除几何缓存，读档后在交通更新时重建。运行期仍按原频率、原车辆顺序执行全部规则。

没有实施车道车辆有序索引、AI 决策降频或并行计算。

## 固定帧对照

Apple M4 / macOS；都会地图、1152 辆小车、8 辆静态公交观察对象。同种子、同物理初始状态，优化前后独立顺序运行，单 CPU、每轮 300 次，共三轮，耗时取中位数。

| 项目 | 优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 小车 Update | 12.34 ms | 5.37 ms | 56.5% |
| 临时分配/次 | 3,441,205 B | 640,618 B | 81.4% |
| 分配次数/次 | 4,618 | 2,060 | 55.4% |

该基准会恢复车辆物理状态，运行期缓存允许复用；旧版恢复时会丢弃部分车身缓冲。因此它能验证固定输入下的计算收益，但分配量不等于真实游戏稳态分配率，也不能直接换算 FPS。完整游戏结果单独测量。

## 真实游戏短场景

使用独立 Ebitengine 窗口，包含公交驾驶、完整交通更新、碰撞与绘制。前后构建顺序运行、相同种子与场景，均启用 CPU profile；前 10 次更新作为预热。下表为一次成对运行的平均值，不是多轮置信区间。

| 场景 | 优化前 Update | 优化后 Update | Update 减少 | Draw CPU 提交前→后 |
| --- | ---: | ---: | ---: | ---: |
| 1152 小车＋8 AI 公交 | 17.90 ms | 10.32 ms | 42.3% | 0.79→0.71 ms |
| 1152 小车＋48 AI 公交、4×视野 | 31.70 ms | 12.16 ms | 61.6% | 1.61→1.51 ms |

8 公交请求 360 次更新，剔除预热后前/后记录 351/350 次更新，107/299 次绘制；48 公交请求 240 次更新，前/后均记录 230 次更新，46/224 次绘制。Ebitengine 会合并更新、跳过部分绘制，所以两类回调分别计数。Draw 为 CPU 提交时间，不是 GPU 帧耗时。

## 两分钟最高负载长测与限制

新版单独运行 1152 小车＋48 AI 公交、4×视野，完成约 120 秒仿真（请求 7200 次更新，剔除预热后记录 7194 次更新）：

| 指标 | Update 耗时 |
| --- | ---: |
| 平均 | 27.63 ms |
| P50 | 27.60 ms |
| P95 | 33.71 ms |
| P99 | 40.79 ms |
| 最大 | 105.75 ms |

长测会经历持续排队及多个信号周期，负载不同于刚开始的短场景。它没有同帧数旧版长测对照，不能把上述短测旧版均值与长测新版均值作为前后比较。长测中还做过约 3 秒进程栈采样；没有同时运行测试套件或其他性能基准。

结论：第 1、2 步在固定帧和短游戏场景中均有明确收益，但最高公交负载的长测依然超过 60 FPS 对应的 16.67 ms 更新预算，尚不能保证稳定 60 FPS。后续可按实际线路/公交数量和拥堵存档判断是否继续做车辆索引或分层决策；本轮保留现有仿真调度。

## 验证

- `go test -short ./...`：通过。
- `go vet ./game ./internal/traffic ./internal/autopilot ./internal/sim ./cmd/release-check`：通过。
- 五张地图各 1152 辆小车，缓存版与全量路口查询/原采样版逐帧完整状态对照：每地图 180 帧，通过。
- 六张地图、五种车道宽度，对比原始路口几何与空间包含查询，覆盖负坐标、不同边距、环岛与 JSON 往返。
- 转弯采样逐项对照原算法，覆盖不同车道宽度、车头方向、车辆尺寸、剩余路点与路径原地修改；缓存模板与运动状态的独立性检查通过。
- 内侧左转绿灯等待、侧后方车队、掉头、靠站、共用始发站与存档回归包含在完整快速测试中。

复现新版：

```sh
go test ./internal/traffic -run '^$' -bench '^BenchmarkTrafficFrame/map0/cars1152$' -benchtime=300x -count=3 -cpu=1
go run ./cmd/release-check -only-scene 4 -frames 360 -output /tmp/bus-perf-8
go run ./cmd/release-check -only-scene 31 -frames 240 -output /tmp/bus-perf-48
go run ./cmd/release-check -only-scene 31 -frames 7200 -output /tmp/bus-perf-48-long
```

真实场景命令会打开独立测试窗口。`frames.json` 中保留 Update/Draw 分别计数、累计耗时和 Update 分位数。
